# 회의 요약 신뢰성 설계

**날짜:** 2026-08-01
**상태:** 승인됨

## 목표

회의 요약 생성이 실패했을 때 사용자가 실패 이유를 노트를 다시 열어도 확인할 수 있게 하고, 요약이 없다는 이유로 노트 화면의 레이아웃이 비거나 플로팅 툴바와 겹치지 않게 한다.

또한 `Same as spoken language` 설정이 실제 발화 언어를 기준으로 동작하게 한다. 한국어로 전사된 녹음에서 로컬 모델이 영어 요약을 반환하면 그 결과를 저장하지 않고, 언어 불일치로 기록해 다시 만들 수 있게 한다. 발화가 혼합된 경우에는 주된 발화 언어를 사용한다.

## 조사 결과

- 2026-08-01 02:17의 Quill Dev 녹음은 전사와 후처리에 성공했고, 첫 클라우드 요약 요청만 실패했다.
- 당시 Dev 앱의 회의 요약 모델은 클라우드 `openai/gpt-oss-120b`였다. 현재 구현은 실패 HTTP 상태와 제공자 오류 코드를 저장하지 않아, 이미 지나간 그 요청의 정확한 제공자 오류는 복구할 수 없다.
- 같은 녹음을 로컬 `qwen2.5-7b-instruct`로 다시 요약한 결과는 저장됐지만 영어 본문을 포함했다. 녹음의 저장된 전사 언어 코드는 `ko`였다.
- `Same as spoken language`의 저장값은 빈 문자열이다. 현재 빈 문자열은 요약 프롬프트에서만 “전사문의 주 언어”를 권장하고 결과 언어 검증에서는 미지정으로 처리된다. 따라서 영어 응답이 통과했다.
- 현재 `PipelineHistoryItem.transcriptionLanguageCode`는 실제 감지 언어가 아니라 사용자가 선택한 전사 언어를 저장한다. `Auto Detect`는 그대로 `auto`로 남는다.
- 요약이 없는 첫 생성이 실패하면 `NoteBrowserView`의 Summary 영역은 배너만 렌더링한다. 콘텐츠 영역이 높이를 채우지 않아 하단 플로팅 툴바와 실패 배너가 겹쳐 보인다.

## 범위

### 포함

- 실제 발화 언어의 수집, 보존, 기존 `auto` 항목 보완
- `Same as spoken language`의 프롬프트·검증 강제
- 성공 및 실패 요약 시도에 대한 안전한 진단 기록
- 요약이 없는 실패 상태의 안정된 화면
- 기존 요약 재생성 실패 시 기존 요약 보존
- 저장 형식 하위 호환성 및 자동 테스트

### 제외

- 사용자가 수행할 실제 GUI 앱 검증
- 제공자 응답 본문, 전사문, 프롬프트, API Key의 진단 저장
- 회의 요약과 무관한 전사·후처리 UI 재설계

## 설계

### 1. 발화 언어를 전사 결과로 모델링

전사 서비스는 문자열만 반환하지 않고, 다음 정보를 포함한 결과를 반환한다.

- 정규화된 전사문
- 확정 발화 언어 코드
- 언어 결정 근거

언어 결정 근거는 다음 우선순위를 갖는다.

1. 사용자가 명시한 전사 언어(`ko`, `en` 등): 그 언어를 확정값으로 사용한다.
2. Auto Detect의 전사 엔진 응답: Native Whisper JSON 또는 클라우드 `verbose_json`의 감지 언어를 지원 코드로 정규화해 사용한다.
3. 엔진이 감지 언어를 반환하지 않는 Auto Detect: 전사문 전체에서 주된 언어를 판별해 사용한다.
4. 판별 불가: 언어 코드를 확정하지 않는다. 이 경우 `Same as spoken language` 요약을 임의 언어로 실행하지 않고, 출력 언어를 명시하라는 복구 안내를 제공한다.

여러 언어가 섞인 전사문은 전사 엔진이 반환한 주된 언어를 우선한다. 엔진 값이 없을 때만 전사문 기반 판별의 주된 언어를 사용한다.

`PipelineHistoryItem`에는 기존 `transcriptionLanguageCode`를 유지한다. 이 값은 사용자가 전사 시 선택한 언어라는 기존 의미를 보존한다. 별도의 선택적 `spokenLanguageCode`와 `spokenLanguageResolution`을 추가해 실제 발화 언어와 결정 근거를 저장한다.

기존 노트의 `spokenLanguageCode == nil` 또는 `transcriptionLanguageCode == "auto"`는 요약 생성 시 전사문 기반 판별로 보완한다. 이 보완 결과는 안전하게 히스토리에 저장한다. 판별 불가 항목은 명시 출력 언어가 선택되기 전까지 생성하지 않는다.

### 2. `Same as spoken language`를 실제로 강제

`meetingSummaryOutputLanguage`가 빈 문자열이면 `MeetingSummarySource`를 만들 때 해결한 실제 발화 언어를 요약 언어로 사용한다. 이 언어는 다음 두 위치에 같은 값으로 전달한다.

- `MeetingSummaryPromptFactory`: 생성 문장은 확정된 발화 언어로 작성하도록 지시한다. 원문 인용은 번역하지 않는다.
- `MeetingSummaryOutputValidator`: 생성 문장 전체가 확정된 발화 언어인지 검증한다.

사용자가 Korean, English 등의 출력 언어를 명시하면 그 선택이 발화 언어보다 우선한다.

언어 불일치 결과는 `MeetingSummaryOutputValidationError.languageMismatch`로 거부한다. 새 요약은 저장하지 않으며, 이전 요약이 있으면 계속 보존한다. 이 실패는 언어 기준과 함께 안전한 진단으로 기록한다.

언어 정보는 요약 본문의 신뢰도와 표시 설명을 위한 생성 스냅샷으로 저장한다. 스냅샷에는 다음만 포함한다.

- 요청한 출력 언어 설정
- 실제 적용 언어 코드
- 적용 근거(명시 설정, 명시 전사 언어, 엔진 감지, 전사문 판별)
- 결과 언어 검증 상태

전사문·프롬프트·모델 원문 응답은 포함하지 않는다.

### 3. 안전한 회의 요약 시도 기록

`PipelineHistoryItem`에 요약 본문과 분리된 선택적 `meetingSummaryAttempt` 기록을 추가한다. 새 기록은 마지막 시도의 상태를 나타내며, 성공 요약을 실패로 덮어쓰지 않는다.

기록 항목은 다음으로 제한한다.

- 시도 시각 및 성공/실패 상태
- 백엔드 종류(local/cloud), 모델 ID, 제공자 호스트
- 적용 언어와 언어 결정 근거
- 실패 분류(인증, rate limit, 타임아웃, 네트워크, HTTP 실패, 응답 형식, 검증 거부, 입력 불가, 저장 실패)
- HTTP 상태 코드 및 제공자 오류 코드(있을 때만)

기록하지 않는 항목은 다음과 같다.

- API Key와 인증 헤더
- 제공자 응답 본문과 오류 메시지 원문
- 전사문, 캘린더 세부 내용, 프롬프트
- 로컬 모델 프로세스의 원시 표준 출력·표준 오류

각 시도 기록은 제출한 소스 스냅샷의 선택적 fingerprint도 함께 보관한다. fingerprint는 이미 요약 envelope에 쓰는 전사문·캘린더 기반 안전 메타데이터이며, 언어 문맥을 추가하지 않는다. 현재 소스와 fingerprint가 일치하는 실패 기록만 Summary UI의 현재 진단으로 표시한다. 이전 버전 기록처럼 fingerprint가 없는 기록은 계속 디코딩하되 현재 진단으로 표시하지 않는다.

요약 생성 결과는 소스 fingerprint 외에 노트별 요약 lifecycle revision에도 묶인다. 사용자가 요약을 삭제하면 해당 revision을 무효화하므로, 진행 중인 재생성 완료가 삭제한 요약을 되살릴 수 없다. 소스 변경 또는 lifecycle 무효화는 제공자 실패가 아니라 로컬 취소이며 새 실패 시도로 저장하거나 일시 실패 UI로 표시하지 않는다.

`MeetingSummaryError`는 현재처럼 제공자 오류를 버리지 않고, 안전한 분류와 상태·코드를 `QuillUserIssueContext` 및 시도 기록에 전달한다. 사용자 문구는 간결하게 유지하되, Details에서 모델·호스트·HTTP 상태·제공자 오류 코드·적용 언어를 확인할 수 있게 한다.

새 요약 저장 또는 시도 기록 저장이 실패하면 현재 화면에는 일시적으로 실패 상태를 보여 주되, 저장됐다고 주장하지 않는다. 이전에 저장된 요약은 유지한다.

### 4. 실패 화면과 재시도 동작

`NoteBrowserView`는 Summary 탭에 다음 세 가지 상태를 명확히 분리한다.

1. **저장된 요약 있음**: `MeetingSummaryView`를 표시한다. 마지막 재생성이 실패했다면 상단 경고 배너와 세부 진단을 표시하지만 저장된 요약은 계속 읽고 복사할 수 있다.
2. **요약 없음 + 실패 진단 있음**: `SummaryGenerationFailureView`를 표시한다. 이 뷰는 스크롤 가능하거나 가용 높이를 채우는 컨테이너 안에 배치해, 실패 배너만 렌더링되어 빈 영역과 플로팅 툴바가 겹치는 일을 막는다. 실패 설명, 안전한 Details, 다시 만들기 동작, Transcript로 돌아가기 동작을 제공한다.
3. **요약 없음 + 실패 진단 없음**: Summary 탭은 표시하지 않는다. 기존 전사 화면과 Create Summary 동작을 유지한다.

닫기 또는 Transcript로 돌아가기는 화면의 임시 오류만 정리한다. 저장된 `meetingSummaryAttempt`는 삭제하지 않아 노트를 다시 열어도 실패 이유를 확인할 수 있다.

재시도 시작 시 임시 오류를 정리하고 생성 중 상태를 표시한다. 성공하면 새 요약과 성공 시도 기록을 저장하고 Summary 탭을 연다. 실패하면 이전 요약의 존재 여부에 따라 위의 1번 또는 2번 상태로 돌아간다.

### 5. 저장 형식 호환성

`MeetingSummaryEnvelope`의 새 생성 스냅샷 필드와 `PipelineHistoryItem`의 새 시도 기록 필드는 모두 선택적으로 디코딩한다.

- 기존 schema v1/v2 요약은 계속 읽고 표시한다.
- 예전 노트에 새 진단 필드가 없으면 Details에 기록 없음으로 표시한다.
- 기존 요약의 액션 항목 완료 상태 보존 동작은 유지한다.
- 마이그레이션은 새 선택적 저장 속성을 추가하는 방식으로 수행한다. 과거 SQLite 히스토리와 인메모리·복구 저장소도 같은 기본값을 제공한다.

## 구현 단위

### 전사 언어 해석

- `TranscriptionService`, `NativeWhisperRuntime`, 클라우드 전사 응답 파서가 전사문과 감지 언어를 함께 반환한다.
- `TranscriptionLanguage`에 지원 코드 정규화와 전사문 기반 주 언어 판별 진입점을 둔다.
- `AppState`의 완료·재시도·복구 경로가 확정 발화 언어와 근거를 `PipelineHistoryItem`에 저장한다.

### 회의 요약 도메인

- `MeetingSummaryModels`에 언어 스냅샷과 시도 기록 모델을 추가한다.
- `AppState.meetingSummarySource(for:)`가 실제 발화 언어를 해결하고, 판별 불가 시 명시 출력 언어 선택을 요구한다.
- `MeetingSummaryService`, `MeetingSummaryPrompt`, `MeetingSummaryOutputValidator`가 같은 실제 적용 언어를 사용한다.
- `MeetingSummaryError`와 `QuillUserIssue`가 안전한 실패 분류를 보존한다.

### 히스토리·UI

- `PipelineHistoryItem`, `PipelineHistoryStore` 및 영속 모델이 실제 발화 언어와 마지막 시도 기록을 선택적으로 저장한다.
- `NoteBrowserView`에 높이를 안정적으로 채우는 첫 생성 실패 화면을 추가한다.
- 기존 요약이 있는 재생성 실패에는 배너만 추가한다.

## 테스트

### 전사·언어

- 명시 `ko` 선택은 실제 발화 언어 `ko`로 저장된다.
- Auto Detect 응답의 `ko` 감지값이 저장된다.
- 감지값 없는 Auto Detect는 전사문에서 주된 언어를 판별한다.
- 혼합 언어 전사문은 주된 언어를 사용한다.
- 판별 불가 Auto Detect 노트는 `Same as spoken language` 생성 대신 명시 언어 선택 안내를 낸다.

### 회의 요약

- `Same as spoken language`와 발화 언어 `ko`에서 영어 생성 결과는 저장되지 않고 `languageMismatch`로 기록된다.
- 명시 Korean·English 출력 언어는 발화 언어보다 우선한다.
- 성공 요약은 적용 언어·근거·언어 검증 상태를 보존한다.
- 클라우드 HTTP 실패, rate limit, 타임아웃, 로컬 런타임 실패, 응답 형식 오류, 검증 거부가 각각 안전한 시도 기록으로 남는다.
- 진단 직렬화 결과에 API Key, 응답 본문, 전사문, 프롬프트가 포함되지 않는다.
- 기존 요약 재생성 실패는 기존 본문과 액션 완료 상태를 유지한다.

### 히스토리·UI 계약

- 이전 요약 schema와 새 선택 필드가 없는 히스토리를 계속 디코딩한다.
- 새 시도 기록은 앱 재시작 뒤에도 노트를 다시 열어 표시된다.
- 저장 실패 시 일시 UI 오류는 표시하지만 영속됐다고 주장하지 않는다.
- 첫 생성 실패에서 Summary 탭과 실패 전용 화면이 표시되고, 콘텐츠 영역이 가용 높이를 채운다.
- 실패 화면의 다시 만들기·Transcript 복귀가 안정적으로 동작한다.
- 기존 요약이 있을 때 실패 배너와 요약 본문이 함께 표시된다.

## 검증 범위

구현 후 관련 자동 테스트와 전체 `make test`를 실행한다. 실제 Quill GUI 앱에서의 재생성·화면 검증은 사용자가 직접 수행한다.
